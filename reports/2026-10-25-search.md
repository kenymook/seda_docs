# Search: общий поиск Files и Chat

Статус: experimental реализация опубликована в приватной версии51 по прежнему адресу. Общая цель зрелости библиотеки остаётся открытой.

Files и Chat используют общий Search установленного `@seda-ai/ui`: TextField и sibling IconButton очистки, native Link/Button результатов, Text и исходные иконки. В Files сохранены существующие фильтры, документы и selection; внешний results region остаётся смонтированным при просмотре уведомлений, а начало поиска возвращает файлы без потери фокуса. В Chat поиск живёт внутри настоящего Modal с начальным фокусом input и native links. Обычное открытие — прежний SPA owner, modified click — браузерная новая вкладка.

Data layer владеет источником, ранжированием, debounce, transport/abort и сохранением. Компонент сверяет точный query и opaque queryKey для результатов, ошибок и loading. Поздний A1 не становится доступным после A1→B2→A3. Ключ меняет владелец на каждый новый remote intent/retry. Remote search service не симулируется; реальные consumers фильтруют локальные файлы и сообщения. Callback composition flag позволяет владельцу дождаться IME commit. Query не сохраняется библиотекой и не отправляется в аналитику.

Целевые preflight проверки: installed React18 consumer160 выбранных случаев (144 results width/theme/size/variant/state плюс16 external-filter),26 invalid models, SSR/Strict hydration, query identity/ABA/stale errors/loaders, keyboard, IME event guard, duplicate intent/retry, focus repair, long content, reduced motion и контраст. Реальные Files/Chat —48 viewport/theme/profile случаев. Baseline авторских данных установлен реальной операцией Files и реальным сохранением Chat; поиск и параметры UI не переписывают JSON. Проверено открытие новой вкладки и сохранение текущего document при SPA navigation. Это предварительный проход; результаты полного прогона приведены ниже.

Визуальный проход Light/Dark нашёл бледное содержимое disabled result и исчезавший зазор caption внутри host reset. Данные результата оставлены читаемыми, недоступность действия объясняет текст; spacing принадлежит Search. Ряды с/без иконки имеют общую колонку без фиктивных glyphs. Повторные попытки Popup-наблюдения исправлены на BrowserContext page event по уже проверенному native-link подходу Sidebar. Первый реальный app-проход выявил Ctrl+K, ограниченный фокусом внутри React root; shortcut owner перенесён на window с composition/repeat/modal/menu/Alt/Shift guards. Исходный снимок этого отказа сохранён отдельно. Assertions не удалены, baselines не переписывались.

API, дополнительные props и причины, token fallback geometry и границы описаны в specs/overlays-layout/search.md. Standalone anchored overlay host, Figma6739:599 (service quota), screen readers/native OS IME/Firefox/WebKit/performance остаются открытыми.

Первый полный Lab остановился в старом glyph assertion: Search prefix использует search.input.icon.default/active, а тест сравнивал его с основным текстом TextField. Отдельная подготовительная сборка была корректно отвергнута stale-installed-package guard: параллельный package verifier пересобрал канонический dist после установки pilot. После завершения verifier выполнены последовательные npm ci/build; отклонённая сборка не опубликована. Первые отказы сохранены рядом с финальными логами.

Полный production Search automation остановился на загрузке нативной Ctrl-click вкладки: вместо Chat показан Sites sign-in. Origin-scoped route/context-header и явный same-URL preview bootstrap не завершили этот путь. Этот отказ не объявлен PASS и assertions не удалены. В реальном in-app браузере с обычным доступом владельца отдельно выполнен Ctrl-click по результату: новая вкладка загрузила выбранный чат, исходный Modal остался открыт. Затем Enter в исходном Modal закрыл поиск и открыл чат в том же tab. Снимки сохранены; это отдельная UI-проверка, не замена незавершённому автоматическому production runner. Полные Windows и Linux Search assertions прошли без такого ограничения на локальном сервере.
