# SEDA AI Первый этап исполняемой модели

> Историческая фиксация этапа 1. Текущие авторские данные пилота перенесены в [пакет контрактов](../../../packages/seda-contracts/README.md). Статус этапа 2 и команды проверки: [phase-2.md](phase-2.md).

Пилот фиксирует основу для перехода от спецификаций к исполняемым контрактам на трёх существующих React-компонентах: Button, IconButton и TextField. Основной сценарий — форма настроек с названием проекта, сохранением и вспомогательным действием.

**Исходная версия:** `354e19adc00605c422033a53ed1dd81dc33259ae`. **Дата фиксации:** 22 октября 2026, UTC. **Область:** web, мышь и клавиатура. Figma metadata используется из спецификаций указанного коммита; отдельная проверка живой Figma-библиотеки не включена.

## Решение первого этапа

Для пилота выбран профиль **Light / regular / m**, управляемое строковое значение поля и единый владелец состояния формы. Размеры и радиусы следуют существующей шкале SEDA. Ошибка поля передаётся через реальный `errorText`; недоступность через `disabled`; loading через `loading` действия и guard формы.

Исходная библиотека сохраняется в baseline без исправлений. Несоответствия зафиксированы вместе с решениями, которые должны быть реализованы на следующих этапах. Этот пакет не объявляет готовыми ни движок конфигурации, ни валидатор, ни соответствие всей библиотеки контрактам.

## Итоговый профиль формы

- Назначение: изменение названия проекта.
- Начальная тема: `Light`; DOM-адаптер существующего portal resolver: `data-theme="light"`.
- Плотность: `regular`; размер: `m`. Плотность и размер независимы.
- TextField: видимый label «Название проекта», `type="text"`, `required`, `value` и `onChange`.
- Сохранение: Button `primary`, `type="submit"`, текст «Сохранить».
- Сброс изменений: Button `secondary`, `type="button"`, текст «Отмена».
- Помощь: IconButton `ghost`, `type="button"`, `aria-label="Справка о названии проекта"`, иконка 16 × 16; рядом видимое пояснение. Персистентный `selected` не применяется.
- Единственная проверка значения в этом сценарии: `trim(value).length > 0`. Сообщение: «Введите название проекта.».
- Валидация после blur или submit. После показа ошибки она переоценивается при изменении значения.
- Form владеет значением, touched, attemptedSubmit, ошибками, saving и snapshot отправленного значения.
- Результат сохранения относится к отправленному snapshot и не перезаписывает более поздний ввод.
- Ошибка сервиса — ошибка формы; корректное поле не получает ложную ошибку.

Это политика конкретного примера, а не универсальный набор ограничений для любого TextField.

## Критерий завершения первого этапа

1. Известны API, фактические defaults, обязательная анатомия и используемые состояния трёх компонентов.
2. Для наблюдаемых расхождений определено рабочее решение либо явная граница поддержки.
3. Все существующие token references профиля проверены; отсутствующий token явно обозначен как планируемый.
4. Задан один точный профиль и владелец состояния формы.
5. Сохранён воспроизводимый reference fixture исходной реализации.
6. Следующие задачи отделяют формализацию контракта от исправления runtime.

Дальнейшая готовность подтверждается выполнением задач в [implementation-handoff.md](implementation-handoff.md), а не наличием этого пакета документации.
