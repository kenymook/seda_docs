## Этап 3 Реальный параметрический пример

| Задача | Решение | Условие приёмки |
| --- | --- | --- |
| R01 Token bridge | Подключить реальные component branches к CSS трёх компонентов | Изменение component token влияет на соответствующую роль; unresolved reference даёт issue |
| R02 Геометрия | Общие размерные пресеты, border-box control, размерная типографика TextField, нормализация иконок/spinner | Измеренные control heights/radii совпадают с выбранным профилем |
| R03 Состояния цветов | Реализовать только состояния матрицы пилота: Save primary — обычные DOM states и loading; Cancel secondary — обычные DOM states и disabled при saving; Help ghost — обычные DOM states без loading; TextField — default/hover/focus/error/disabled | Изменения исходят из существующих token roles; focus остаётся независимым |
| R04 Focus TextField | Связать индикатор с реальным input focus | Индикатор виден при клавиатуре, включая error; выставление data-state не заменяет DOM focus |
| R05 Loading Button | Сохранить label, width и focus; заблокировать активацию | Width до/во время loading не меняется в заявленном slot layout |
| R06 API consistency | Исправить default IconButton, согласовать errorText и disabled policy, объединять description IDs | Default входит в enum; error требует текста; внешний description сохраняется |
| R07 Missing token | Добавить text-field/border/disabled alias отдельно, с проверкой целевого semantic leaf | До добавления ссылка не считается существующей; после добавления разрешается в Light/Dark |
| R08 Один профиль | Настройки темы, density и size применяются к реальному React-render | Зависимые компоненты обновляются без ручного редактирования каждого CSS |
| R09 Form controller | Controlled input, validation, submit guard, snapshots, save failure/retry | Поздний ответ не перезаписывает ввод; повторная отправка не стартует |
| R10 Explain | Источник итогового значения собирается из выполненного resolution | Объяснение соответствует фактическому применённому значению |

Простой baseline fixture сохраняется как исходная точка. Новый профиль не должен использовать baseline-переключатели как доказательство реализации dependency engine.

## Этап 4 Проверки доверия к результату

Минимальная матрица:

1. Основной сценарий сохраняет корректное имя.
2. Пустое или состоящее из пробелов имя даёт сообщение, value сохраняется, фокус возвращается в input.
3. После ошибки корректный ввод снимает ошибку согласно политике.
4. Повторный click и submit через Enter во время saving не запускают новое сохранение.
5. Input error и keyboard focus видны одновременно.
6. Поздний ответ на старый snapshot сохраняет более новые правки.
7. Сбой сохранения показывает form error и позволяет retry текущего значения.
8. Theme/size/density update сохраняет пользовательские данные.
9. Неверный enum, неизвестный token и отсутствующее accessible name дают адресные нарушения.
10. Отсутствующий полный Tooltip или иной незакрытый контракт помечается как не проверено/требуется решение.

Необходимые статусы: пройдено, нарушено, требуется решение, не проверено. Один общий Health не заменяет способы проверки.
