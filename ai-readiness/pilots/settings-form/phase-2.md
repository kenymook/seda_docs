## Что теперь можно выполнить

Из корня репозитория, с Node.js 24 или новее:

```bash
cd packages/seda-contracts
npm ci
npm run validate
npm test
npm run compile -- --theme Dark --size l --output .generated/settings-dark-l.json
npm run context -- --output .generated/context.md
```

Профиль поддерживает Light/Dark × `s/m/l/xl`, пока только при плотности `regular`. Изменение `configuration.controlSize` обновляет размер всех recipes и размерные значения в результате. Повторная ручная запись `size` в props отклоняется. Binding проверяется на весь домен значений: ошибочную связь `disabled` с `form.fieldError` нельзя скрыть начальным `undefined`.

Компиляция выдаёт данные геометрии, типографики, layout, props, token branches и формы с объяснимыми источниками. Для размеров сохранены высоты 24/32/40/48 px и радиусы 6/8/10/12 px; padding Button меняется 8/12/16/20 px. Padding TextField 10 px и общие gaps `regular`-профиля остаются постоянными. Web-адаптер преобразует вес label `Semibold` в 600.

Вывод идёт в stdout или заданный файл; `.generated/` игнорируется Git. JSON-контекст доступен через `npm run context -- --json`.

## Обнаруженное несоответствие остаётся видимым

```bash
npm run audit
```

Для текущего кода команда возвращает **код 1**: observed default IconButton — `neutral`, тогда как тип допускает другой набор вариантов, а целевое решение задаёт `secondary`. Профиль явно использует `ghost`, поэтому его данные могут пройти проверку одновременно с отрицательным результатом аудита библиотеки. Target default хранится отдельно и не выдаётся за уже внесённое исправление.

Проверки выявляют также неизвестные props, недопустимые значения native props, отсутствующие токены, несуществующие проверки, конфликтующие bindings и ошибочные сочетания состояний. В отчётах сохраняются коды, адреса данных и статусы отдельных проверок.

## Граница готовности

**Завершены модель и проверка данных пилота.** Публичные компоненты, CSS и глобальные токены на этом этапе не изменялись.

- **13 браузерных проверок — `not-checked`.** Сюда входят геометрия рендера, видимый фокус, стабильность ширины loading, CSS-привязки и composition описаний. `runtimeConformance` сохраняется как `not-checked`.
- **D16 — `decision-needed` в обеих темах.** Semantic target существует, но отсутствующий component token `text-field/border/disabled` не фабрикуется resolver-ом.
- **Форма проверена как модель.** Save/focus представлены эффектами. Модель сохраняет редактируемый ввод во время запроса, связывает ответ с ID и snapshot и игнорирует устаревшие ответы; реальный backend и DOM-фокус подключаются позже.
- **React bindings ограничены явным форматом.** `$handler` и `$slot` описывают интерфейс адаптера. Произвольные JavaScript-функции, визуальное содержимое ReactNode и полная доступность требуют дополнительных проверок.
- **Полный Tooltip вне области пилота.** Для Help принято видимое пояснение. Native `title` не подтверждает поведение hover/focus/Escape. Touch hit area, все визуальные варианты и живая Figma-библиотека также не объявлены проверенными.
