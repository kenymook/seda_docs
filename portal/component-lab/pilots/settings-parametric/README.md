# SEDA AI — параметрическая форма настроек

Живой React-пилот третьего этапа: **Button, IconButton и TextField из `packages/seda-ui`** получают размеры, цвета и связи из [исполняемого профиля](../../../../packages/seda-contracts/profiles/settings-form.json). Настройки Light/Dark и `s/m/l/xl` применяются ко всей форме; ввод, ошибки, текущий запрос и состояние справки сохраняются.

Пилот использует существующую [модель событий](../../../../packages/seda-contracts/src/form.mjs) и [web-адаптер](../../../../packages/seda-contracts/src/web.mjs). Логика валидации и сохранения не переписана внутри React-компонента.

## Запуск

Требуется Node.js 24 или новее. Из корня репозитория:

```bash
npm --prefix packages/seda-contracts ci
cd portal/component-lab/pilots/settings-parametric
npm ci
npx playwright install chromium
npm run build
npm run serve
```

Открыть **http://127.0.0.1:5184/**. Шрифты Inter с кириллицей и весами 400/600/700 устанавливаются через закреплённый пакет `@fontsource/inter` и входят в локальную сборку. Загрузка страницы не обращается к внешнему сервису шрифтов.

Для проверки, во втором терминале из этой же папки:

```bash
npm run typecheck
npm run verify
```

Сервер должен продолжать работать. Если Chromium установлен в общем каталоге, передать `PLAYWRIGHT_BROWSERS_PATH` и установке, и запуску проверки. Версия Playwright зафиксирована в `package-lock.json`.

## Что можно попробовать

1. Изменить тему и размер в панели «Профиль». Высота, радиус, типографика и нормализованные иконки обновятся совместно. Доступная плотность — `regular`.
2. Очистить название или ввести пробелы и нажать «Сохранить». Модель возвращает ошибку и фокус в поле. После первой показанной ошибки ввод повторно проверяется при изменении.
3. Выбрать ручной ответ демо-сервера, сохранить значение **A**, затем ввести **B**. Ответ «Успех» фиксирует сохранённое **A** и оставляет **B** в поле как несохранённое изменение.
4. Выбрать ошибку демо-сервера и повторить сохранение. Ошибка запроса относится к форме; новая попытка отправляет текущее значение.
5. Раскрыть «Откуда берутся значения». Таблица показывает назначенные CSS-переменные, значения и фактические цепочки разрешения токенов для выбранного элемента.

Сохранение — локальная имитация транспорта. При автоматическом ответе используется задержка; ручной ответ позволяет воспроизвести позднее завершение. Сервер приложения не записывает проект и не обращается к продуктовой базе данных.

## Как устроена сборка

| Файл | Ответственность |
| --- | --- |
| [build.mjs](build.mjs) | Читает реальные токены и контракты, проверяет их и defaults исходников, компилирует каталог из восьми профилей, проверяет полноту web-привязок и собирает React-приложение |
| [app.tsx](app.tsx) | Отрисовывает компоненты, связывает recipes с состоянием формы, исполняет save/focus-эффекты модели и предоставляет диагностический API |
| [styles.css](styles.css) | Оформляет лабораторию и размещает форму через разрешённые layout-переменные; не задаёт собственные значения размеров и цветов трёх контролов |
| [server.mjs](server.mjs) | Отдаёт статическое содержимое `dist/` на локальном адресе |
| [test-fixtures.tsx](test-fixtures.tsx) | Дополнительные реальные экземпляры компонентов для проверки slot layouts, description IDs и disabled/error; появляются только при `?review=1` |
| [verify.mjs](verify.mjs) | Выполняет браузерные сценарии и связывает результаты с конкретными browser rules контрактов |

Каталог формируется при сборке из текущих авторских источников. **После изменения `tokens.json`, `system.json`, профиля, контракта, компонента или адаптера необходимо снова выполнить `npm run build`.** Переключатели страницы выбирают уже проверенную конфигурацию из этого каталога. Авторские изменения не считываются заново во время просмотра страницы.

Сборка сохраняет `dist/build-metadata.json`: хэши использованных исходников и токенов, закреплённых зависимостей, итоговых файлов, число конфигураций и результат проверки defaults. Хэши исходников проверяются до и после сборки; изменение файла во время процесса завершает сборку ошибкой. Metadata содержит статус `runtimeConformance: not-checked`: результат сборки сам по себе не подтверждает поведение браузера.

## Владение профилем и адаптером

Размер каждого recipe связан с `configuration.controlSize`. Состояния `loading`, `disabled`, `value`, `errorText` и `aria-expanded` берутся из указанных в профиле bindings. `$handler` и `$slot` разрешаются в реальные функции и React-элементы через `bindWebRecipe`.

Адаптер владеет небольшим набором свойств, необходимых для DOM-связей и исполнения профиля. Их ручная запись в recipe отклоняется с адресной ошибкой `PROFILE_ADAPTER_PROP_CONFLICT`, чтобы авторское значение не заменялось незаметно при рендере:

| Recipe | Свойства адаптера |
| --- | --- |
| Все | `id`, `ref`, `style`, `data-seda-contract`, `data-seda-loading-slot` |
| Save | Дополнительно `onClick`: определение маршрута отправки |
| Help | Дополнительно `aria-controls`: связь с видимым пояснением |
| Project name | Focus-эффект модели выполняется через ref адаптера |

Поддерживаются явные пары обработчиков: Cancel `onClick` → `form.cancel`, Help `onClick` → `form.toggleHelp`, Project name `onChange` → `form.change` и `onBlur` → `form.blur`. Иная запись `$handler` отклоняется с `PROFILE_HOST_HANDLER_UNSUPPORTED` до рендера.

Это ограничение конкретного пилота. Публичный API компонентов продолжает поддерживать допустимые HTML/ARIA-свойства, `style`, обработчики и refs вне этой схемы размещения.

Для Button и IconButton CSS-переменные назначаются на кнопке. Для TextField они назначаются на обёртке `data-seda-contract="TextField"` и наследуются реальным полем: native `style` и остальные свойства input сохраняют своё значение в публичном API.

### Стабильность формы при проверке

Блок поля заранее резервирует одну строку сообщения. Его минимальная высота рассчитывается из **разрешённых** line-height подписи, промежутка до контрола, высоты контрола, промежутка до сообщения и line-height сообщения. `align-content: start` сохраняет размер контрола.

Это устраняет потерю первого клика: показ ошибки на blur не перемещает «Сохранить» между нажатием и отпусканием указателя. Данное резервирование рассчитано на текущую короткую required-ошибку пилота. Многострочные сообщения требуют отдельной проверки размещения.

Справка находится в строке действий после «Отмена», а расстояние от блока поля до строки действий берётся из `fieldsToActions`. Во время loading сохраняются label, отведённое место под spinner, ширина и возможность удерживать фокус. Блокирование повторной отправки также выполняется владельцем формы, включая программный `requestSubmit()`.

## Проверка и доказательства

`npm run verify` проверяет геометрию по восьми профилям, настоящие DOM-состояния, клавиатурный фокус вместе с ошибкой, loading layouts, блокирование повторной отправки, поздние ответы, ошибку/повторную попытку, связи описаний и применение component tokens.

До сценариев verifier сверяет фактические исходники с metadata и байты отданной страницы с локальной сборкой. Проверка изменения токенов создаёт копию исходных токенов, пропускает её через настоящий compiler и web-адаптер, затем сравнивает браузерную отрисовку и цепочку источников. Этот режим доступен через диагностический стенд; обычный интерфейс не предоставляет замену compiled-профиля.

Результаты создаются в `.diagnostics/`:

- `verification.json` — окружение, хэши сборки и verifier, сценарии, измерения, статусы отдельных browser rules и сохранённые ограничения capabilities.
- `settings-light-m.png`, `settings-dark-m.png` — визуальные снимки соответствующих профилей.
- `settings-error-focus.png` — снимок совместного отображения ошибки и фокуса.

Скриншоты помогают визуальной проверке; сами по себе они не являются сравнением с эталоном и не заменяют измерения. `dist/`, зависимости и диагностические результаты исключены из Git. Браузерный отчёт является доказательством только для указанных в нём исходников и окружения.

## Параметры локального запуска

| Переменная | Назначение |
| --- | --- |
| `SEDA_PILOT_PORT` | Порт локального сервера; по умолчанию `5184` |
| `SEDA_PILOT_URL` | Адрес сервера для verifier; по умолчанию `http://127.0.0.1:5184/` |
| `SEDA_PILOT_DIST` | Отдельный каталог сборки; одинаковый для build, server и verifier |
| `SEDA_PILOT_OUTPUT` | Каталог результатов браузерной проверки |
| `SEDA_TOKENS_FILE` | JSON-файл с экспериментальной копией токенов для сборки; передаётся также verifier для сверки источника |
| `SEDA_REPO_ROOT` | Может указывать только на checkout, которому принадлежит этот пилот; другой каталог отклоняется после сравнения realpath |

Для эксперимента с токеном использовать копию `tokens.json` и отдельный output-каталог. Импорты React-компонентов, модели и compiler привязаны к текущему checkout, поэтому произвольный другой репозиторий не объявляется источником исполняемого кода.

## Граница проверки

Область пилота — веб, указатель и клавиатура, Light/Dark, четыре размера и `regular`. Браузерные сценарии запускаются в закреплённом Chromium. Полный Tooltip, touch hit areas, все визуальные варианты библиотеки, uncontrolled tracking, продуктовый backend и полная проверка доступности остаются отдельными задачами. Статусы capabilities сохраняются в отчёте и не подменяются результатом этого пилота.

Исходный [baseline-стенд](../settings-baseline/README.md) сохранён для сравнения. Общий контекст и задачи этапа находятся в [handoff пилота](../../../../ai-readiness/pilots/settings-form/implementation-handoff.md).
