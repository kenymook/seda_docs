# SEDA — UX выпуска конфигурации

Статус: проверяемый UX-прототип, 29 октября 2026. Прототип использует реальные SEDA Button, IconButton, Select, Checkbox, Modal, Alert, Popover и общий header. Цвета оболочки и образцы токенов взяты из SEDA. Выпуски и подключения учебные; запросов к общей базе нет. Это не готовый backend выпуска и не публикация npm-пакета.

## Обещание ближайшей версии

Первый пользователь — владелец SEDA. Он меняет токены, видит точный diff и влияние, выпускает проверенный снимок, понимает, какие приложения обновились, и может безопасно вернуть предыдущую конфигурацию. Бинарный критерий готовности production-версии: этот сценарий самостоятельно пройден на реальном подключённом приложении, включая повторное открытие портала и возврат версии.

В первый выпуск механики входят: существующий owner-private доступ, один общий черновик, неизменяемые версии конфигурации, проверки обеих тем, история, возврат новой версией, один реальный адаптер-потребитель. Выпуск пакета компонентов и автоматическая миграция несовместимой базы — отдельные задачи. Обновление конфигурации само по себе не означает, что npm-пакет или все reference-экраны обновились.

## Смысл состояний

| Понятие | Что означает | Что пользователь видит |
| --- | --- | --- |
| Сохранено на устройстве | Есть локальная резервная копия | Нет сети; выпуск недоступен, изменения сохранены |
| Сохранено в базе | Общий черновик подтверждён сервером | Черновик сохранён; точная основа версии |
| Проверено | Проверен конкретный снимок и база, а не произвольное текущее состояние | Готово к выпуску; проверка аннулируется при изменении |
| Выпущено | Создана неизменяемая конфигурация и переключён current pointer | Номер версии, состав, результат для подключений |
| Применено | Потребитель подтвердил принятую конфигурацию | Версия у конкретного приложения |

Сохранения черновика не засоряют историю выпусков. Термин «Применить» без указания области не используется. На каждом этапе одна основная кнопка: Проверить изменения → Выпустить v… → Посмотреть подключения. Ошибки показывают причину, сохранность данных и следующий шаг рядом.

## Структура экрана

- Общий header и rail 54 px; раздел «Выпуски» с иконкой истории и tooltip. Общая типографика 14 px, заголовок экрана 18 px, без декоративных overline. Цвета — роли SEDA. Активная навигация нейтральная; focus-ring сохраняется.
- Левый sidebar: Изменения, Версии, Подключения; текущая выпущенная конфигурация отдельно от черновика.
- Центр «Изменения»: статус сохранения, точная основа, diff по токенам и темам, проверки, комментарий версии. Выбор строки показывает детали справа.
- Правый sidebar: реальный SEDA Select до/после, переключаемая тема в header, путь происхождения, область влияния. В production hover/read-only и другие состояния должны фиксироваться контроллером preview; простой перекрас default не считается доказательством этих состояний.
- «Версии»: неизменяемая история, отдельная текущая версия, подробности выбранной версии, скачивание её артефакта, возврат. Это не список autosave.
- «Подключения»: приложение, политика обновления, запрошенная и принятая версия, статус/ошибка. Автоматическое и фиксированное подключение различаются словами, не только цветом.
- Диалог выпуска кратко подтверждает область воздействия. Диалог возврата объясняет новую версию и сохранность черновика. Отмена изменений черновика — отдельное разрушительное действие с подтверждением.
- На узком экране rail и навигация переносятся наверх, детали идут за основным содержимым; таблица скроллится внутри области, страница не получает горизонтальное переполнение.

## Приоритетные сценарии

| Приоритет / кейс | Поведение и следующий шаг | Доказательство |
| --- | --- | --- |
| P0. Обычный выпуск | Проверить сохранённый diff → увидеть результат → подтвердить выпуск → увидеть принятую версию Lab | Основной интерактивный сценарий прототипа; реальный адаптер нужен для production |
| P0. Пустой черновик | Нет неактивной загадочной основной кнопки; объяснение и переход в редактор | Empty state |
| P0. Первый выпуск | Нет придуманной прошлой версии; создание v0.1.0 | Отдельный сценарий |
| P0. Нет сети | Продолжение редактирования, локальная копия; выпуск заблокирован; явный повтор синхронизации | Отдельный сценарий; production требует reload/offline QA |
| P0. Сохранение ещё идёт | Проверка/выпуск не используют неподтверждённые данные | Блокировка действия; серверное подтверждение обязательно |
| P0. Две вкладки | Не пересохранять чужое изменение молча; сравнить конфликтные значения и выбрать | Два различающихся результата выбора в прототипе; production нужен three-way merge |
| P0. Ошибка ссылки/типов/цикл | Выпуск недоступен, строка ошибки ведёт к токену; остальные изменения не теряются | Сценарий ошибки ссылки; фактические resolver-проверки выполняет существующая модель |
| P0. Изменение после проверки | Аннулировать проверку, показать необходимость повторной; выпуск старого/нового снимка не смешивать | Guard по revision и автоматический тест |
| P0. Двойное нажатие | Одна операция, действие блокируется, loading не меняет размер | Guard по фазе/operation; серверный idempotency key нужен в production |
| P0. Ошибка выпуска | Текущая конфигурация работает; черновик сохранён; явный retry | Ошибка до создания версии, без ложного успеха |
| P0. Ответ потерян | Не предлагать слепой новый выпуск; проверить исход прежней операции | Сценарий «Ответ потерян», совпадение operation |
| P0. Поздний ответ | Ответ старой операции не меняет новый выбранный сценарий/новую операцию | Guard и отмена таймеров прототипа; Abort и CAS нужны в backend |
| P0. Возврат | Создать новую версию со снимком выбранной; сохранить историю и текущий черновик, сбросить его проверку | История → старая версия → подтверждение → новая текущая |
| P0. Изменение базы библиотеки | Не применять старые пути молча; сохранить/export черновик, показать несовместимость | В прототипе export учебного patch, выпуск заблокирован; миграция не имитируется |
| P1. Предупреждение | Отделить от блокирующей ошибки; осмысленное подтверждение просмотренного риска | Отдельный сценарий и checkbox; это не заявленная WCAG-сертификация |
| P1. Один потребитель не обновился | Выпуск и применение раздельны; показать ошибку у приложения, оставить его last-known-good; retry применения | Спроектировано; production-адаптер не реализован |
| P1. Фиксированная версия | Не переключать самостоятельно; показать необходимость обновления в приложении | Пример подключения с pin |
| P1. Новый выпуск из другой вкладки | Проверить base release вместе с draft revision; показать новый diff и повторно проверить | Требование к production CAS; модель UI не выдаёт это за реализованный сервер |
| P1. Отмена/уход/перезагрузка | Закрытие диалога сохраняет черновик; результат выполняющейся операции восстанавливается по ID после возврата | Modal focus/escape проверяются; durable recovery требует backend |
| P1. История/экспорт | Артефакт принадлежит выбранному снимку, а не текущему черновику | Прототип экспортирует реальный JSON текущего учебного снимка; прошлые артефакты пока недоступны |
| P1. Удаление/переименование токена | Классифицировать как несовместимое изменение, показать потребителей; выпуск только по принятой политике совместимости | В текущий scope редактора не добавлено: нужен отдельный контракт миграции |
| P1. Большой diff | Поиск, группы по слоям/компонентам, независимые списки ошибок; пользователь не должен читать тысячи строк | Поиск и scroll в прототипе; виртуализация по измерению объёма |

## Backend-контракт до реализации

1. Раздельные сущности: shared draft, immutable release, current release pointer, validation result, publication operation, consumer acknowledgment. Не использовать token_history как готовую историю релизов.
2. Снимок выпуска фиксирует source hash, draft revision/content hash, base release, theme coverage, schema/compiler version, изменённые authored-ссылки и артефакт. Номер версии выдаёт сервер.
3. Validation ID привязан к точному снимку и политике проверок. Любое содержательное изменение/новая база делает его недействительным. Сервер повторно проверяет, что выпускается именно проверенный снимок.
4. Publish использует idempotency key и CAS по основе/ревизии. Повтор запроса возвращает ту же операцию. Создание версии и переключение current атомарны. Ошибка/timeout не должны оставлять ложный current.
5. Operation status можно прочитать после потери ответа или перезагрузки. Неизвестный исход — отдельное состояние, а не подтверждённая ошибка или успех.
6. Потребитель проверяет schema/source compatibility и подтверждает применённую версию. Неудача одного потребителя не переписывает историю выпуска; приложение сохраняет last-known-good.
7. Возврат создаёт новую версию из артефакта старой; shared draft не удаляется. Проверка черновика аннулируется относительно новой основы.
8. Доступ наследуется от существующего owner-private портала. Отсутствие формы авторизации не означает публичное право записи. Проверять права и происхождение запросов на сервере; секреты не попадают в артефакты.

## Как оценивать качество

Технические тесты подтверждают состояния и переходы. Они не подтверждают понятность UX или «10 из 10».

Наблюдаемая проверка: владелец без подсказок (1) меняет границу Select, (2) отличает сохранение от выпуска, (3) объясняет влияние на две темы и приложения, (4) выпускает конфигурацию, (5) находит результат после перезагрузки, (6) возвращает старую версию, (7) понимает, что черновик сохранился. Отдельно дать задачу с offline/conflict и потерянным ответом.

Успех: нет потерянных изменений и дубликатов выпуска; пользователь не принимает preview за production; на каждом препятствии выбирает правильное действие без объяснения автора. Фиксировать ошибки/вопросы и корректировать UI. Не назначать высокую оценку только по скриншоту или числу тестов.
