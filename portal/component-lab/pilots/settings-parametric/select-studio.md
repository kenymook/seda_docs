# Select: настройка и сравнение состояний

В Component Studio живой Select дополнен пятью фиксированными визуальными образцами на том же публичном @seda-ai/ui: default, hover, focus, disabled, error. Цвета берутся из существующих компонентных токенов. hover/focus фиксируются только внутри образцов CSS-привязками для сравнения; это не новые состояния или props библиотеки. Нативный список по-прежнему зависит от ОС.

Часть выбирается под живым образцом или через Property group. Нажатие на название состояния открывает его токен в выбранной части; если отдельного токена в ней нет, используется border этого состояния. Назначение роли компонентному токену не меняет саму семантическую роль. В popover показана область изменения и есть переход «Открыть общую роль»; там показывается число и список зависимых токенов для текущей темы.

«Отменить изменение» возвращает предыдущее значение последнего локально изменённого токена; изменение снова проходит существующее автосохранение. Если значение уже заменено внешним обновлением, отмена недоступна, чтобы не перезаписать более новую правку. История отмены относится к текущему сеансу, одно действие. «Вернуть исходное значение» удаляет override выбранного токена. Остальные токены не сбрасываются.

Статус общей базы виден над Select. Конфликты, offline и retry остаются в существующей модели сохранения; база и API не изменены.

API в этом сценарии — изолированная проверяемая fixture, не рабочая D1.

## Границы

warning, success, active, read-only и loading присутствуют в каталоге цветов, но отдельное поведение этих состояний текущего Select не реализовано; на холсте это явно отмечено. Автосохранение настоящей D1 уже проверялось в saved-design.md; в этой задаче протокол/API не изменялся и повторные тестовые записи в рабочую базу не выполнялись. Другие компоненты сохраняют прежние предпросмотры; перенос доски состояний на них — отдельная работа.
