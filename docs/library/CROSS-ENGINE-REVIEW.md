# Проверка SEDA в разных браузерных движках — 26.10.2026

Проверка выполнена на установленном пакете SEDA UI в существующих React-экранах Lab, «Файлы» и редакторе документов. Верификаторы принимают `SEDA_BROWSER_ENGINE=chromium|firefox|webkit`; по умолчанию остаётся Chromium. Отчёты и снимки каждого движка сохраняются в отдельных локальных `.diagnostics-*` каталогах. Это проверка браузерного исполнения, а не подтверждение работы в нативной оболочке десктоп-приложения.

| Экран | Firefox | WebKit | Что проверено |
| --- | ---: | ---: | --- |
| Lab | 56/56 | 56/56 | 4 ширины × 2 темы × 4 размера, X, loading, формулы, форма, таблица, карточки, фильтры, диалог и клавиатура |
| Файлы | 9/9 | 9/9 | Навигация, операции с файлами, сохранение/загрузка, темы, размеры, X/Y |
| Редактор документов | 5 model + 18 browser | 5 model + 18 browser | Редактирование, структура, история, вставка, сохранение, ошибки хранения, темы и плотность |
| Форматирование текста | 5/5 | 5/5 | Выделение, марки, клавиатура, сохранение/загрузка, темы |

В WebKit обнаружено различие при закрытии нативного `<dialog>` клавишей Escape: фокус не возвращался к открывшей кнопке. Lab теперь явно запоминает источник открытия и возвращает ему фокус при закрытии. Повторный прогон WebKit подтвердил сценарий.

Верификатор редактора использовал CDP для списка фактически загруженных шрифтов; эта дополнительная диагностика остаётся только в Chromium. Вычисленные размеры и семейства шрифтов проверяются во всех трёх движках. Также синтетический `ClipboardEvent` в Firefox не передаёт подготовленный `DataTransfer`; тест вставки теперь создаёт событие с явным `clipboardData`, сохраняя проверку plain text и отсутствия HTML-вставки. Число событий `input` при отклонённой правке зависит от движка, поэтому тест проверяет откат и факт всех трёх действий, а не точное число событий.

GitHub Actions запускает эти четыре существующих сценария в отдельных Firefox и WebKit jobs. Общий `library` gate требует успеха обоих движков вместе с package, Lab и references. CI использует штатные браузеры Playwright для Linux; локальные результаты Windows не подменяют результат удалённого запуска.

Первый Linux запуск не собрал пилот без зависимостей `seda-contracts`; шаг установки добавлен в оба jobs. Следующий запуск подтвердил Lab 56/56 и «Файлы» 9/9 в Firefox, но выявил два различия: WebKit оставлял открытым диалог после Escape, Firefox увеличивал пустой `TextArea` сверх высоты профиля и прерывал следующий сценарий редактора. Диалог явно обрабатывает Escape. Тот же Firefox 135 локально показал источник второго дефекта: нативные вертикальные margin по 1 px у `<textarea>` дают 90 px вместо 88 px. Общий CSS TextArea теперь сбрасывает margin; повторный прогон Firefox 135 дал 88 px, margin 0 и 5/5 model + 18/18 browser. Строгая проверка итоговой высоты сохранена.

[Linux CI run #40389044447](https://github.com/kenymook/seda_docs/actions/runs/40389044447) для исправленного head `c3a9d93fc343a87844943c054e6f94b6ad1029ae` завершился успешно во всех шести jobs. Firefox и WebKit по отдельности подтвердили Lab 56/56, «Файлы» 9/9, редактор 5 model + 18 browser и inline marks 5/5; package дал 77/77. Это результаты журналов указанного запуска, а не оценка всех экранов и платформ.

Снимки Lab для Firefox и WebKit просмотрены в светлой и тёмной темах: структура панелей, контролов, таблицы и инспектора согласована на проверенном размере 1440 px. Автоматическая матрица также покрывает 1180, 780 и 390 px. Визуальная приёмка всех reference-экранов относительно исходных Figma-макетов, screenreader/OS проверки, производительность и нативные desktop runtime остаются открытыми. Прогон этих четырёх сценариев не расширяет сам по себе executable contracts остальных компонентов.
