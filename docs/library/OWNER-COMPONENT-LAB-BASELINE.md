# Owner Component Lab: исходная точка

Дата среза: 27 октября 2026. Этот документ фиксирует основу пересборки старого Component Lab в инструмент управления SEDA. Он не объявляет старые HTML-превью компонентами библиотеки и не меняет опубликованную конфигурацию.

## Рабочая основа

- Репозиторий: `kenymook/seda_docs`; чистая интеграционная копия `.integration-lab2`, ветка `codex/seda-lab2-integration-20261023`, commit `c225c85b7dd5b5705b3c735ff6f6faf47a6d077d`, PR #4.
- Публичный UI API: `packages/seda-ui/src/index.ts` — 35 экспортируемых модулей компонентов. Это число не является числом проверенных контрактов.
- Исполняемые контракты: 13 JSON-файлов в `packages/seda-contracts/contracts`, перечисленные в `src/registry.mjs`. Текущий профиль — `profiles/settings-form.json`.
- Источник токенов: корневой `tokens.json`; в коллекции компонентов 52 ветки. Наличие ветки не подтверждает существование публичного React-компонента.
- Живой React Lab: `portal/component-lab/pilots/settings-parametric`, использует установленный `@seda-ai/ui`, контрактный компилятор и `SedaProvider`.
- Старый `portal/component-lab/app.js` загружает `tokens.json` и индекс документации, но строит превью через собственные HTML-шаблоны и `innerHTML`. Его навигация и способ исследования компонентов пригодны как продуктовая основа; показанное им поведение нельзя автоматически считать поведением `@seda-ai/ui`.
- На момент инвентаризации приватный сайт по прежнему URL имел версию 80 с source commit `95363b8b39774fb72d22a568fc2fb3dc87556591`. Исходники Site ведутся в отдельном репозитории, поэтому перед выпуском их нужно сверять с веткой PR.

## Границы первой версии

1. Каталог показывает только реально импортированные публичные SEDA-компоненты. Компоненты с исполняемым контрактом получают пометку «контракт проверяется»; остальные — «публичный API, контракт ещё не подключён». Композиции приложения помечаются отдельно.
2. Тема, размер и разрешённые значения берутся из `packages/seda-contracts/system.json`, контрактов, профилей и `tokens.json`. Каталог и будущий редактор владельца не ведут независимые пресеты.
3. Черновик владельца изменяет допустимые значения и токены, показывает происхождение и зависимые экраны. До проверки и выпуска он не меняет пользовательскую опубликованную конфигурацию.
4. Первый выпуск черновика готовит проверяемое изменение для PR. Прямую публикацию из браузера, права для нескольких владельцев и откат версии проектируем после приёмки этого потока.

## Очередность проверки

1. Инвентаризация: пересечение публичного API, исполняемых контрактов и веток токенов; для каждого элемента указать источник и уровень готовности.
2. На плотном рабочем экране проверить Light/Dark, S–XL, масштаб текста, X/Y, состояния полей и loading; визуально просмотреть результат вместе с автоматическими измерениями.
3. Проверить, что изменение черновика проходит через resolver/компилятор и реально меняет DOM SEDA-компонента; сравнить показанную формулу с фактическим значением.
4. Сверить исходники PR, собранные артефакты и опубликованный Site, сохраняя прежний адрес и приватную ACL.

## Проверка исходной точки

- TypeScript пилота — PASS.
- Контрактные тесты исходной точки на Node 24 — 148/148. Новые проверки owner policy — 2/2.
- Сборка пилота после подключения policy — PASS; 8 профилей, `sourceAudit: true`, SHA-256 токенов `161cda63ac963e6ecdf8708837b3af170974f22491c48419e55ee0e0192b2f4a`.
- Браузерный Lab после окончательной сборки — 56/56 в установленном Chrome. Включены Light/Dark, S–XL, четыре ширины окна, loading, X, сохранение, фильтры и контроль соответствия исходников артефактам. Снимки Light/Dark 1440 px просмотрены; новая policy не меняет прежние значения по умолчанию.
- Контрактный пакет требует Node 24+. Системный Node 22 не поддерживает параметр `--test-isolation=none`. Sandbox также блокировал локальный loopback; браузерный прогон выполнен с разрешённым локальным соединением.
- Owner policy в `packages/seda-contracts/owner-policy.json` теперь задаёт подмножество тем/размеров, их defaults и диапазоны пользовательских контролов. Валидатор отвергает варианты вне исполняемой геометрии и default, скрытый политикой. React Lab читает policy в сборке; границы слайдеров и сброс больше не дублируются в `app.tsx`.
- Первый React Component Lab доступен локально по `/owner.html` и через действие «Component Lab» в панели параметров Lab. Черновик владельца позволяет изменять доступные темы, размеры, defaults и диапазоны, затем применить их к живому предпросмотру или скачать JSON. Публичные компоненты и исполняемые контракты перечисляются из действующих исходников при сборке. Плотный экран использует реальные Button, IconButton, TextField, Select, Checkbox, Radio, Toggle, Table и Slider SEDA; Table и композиция экрана не названы сертифицированным контрактом.
- Проверка нового Component Lab — 13 браузерных групп в Chrome, в том числе отклонение недопустимой геометрии, только Dark, изменение диапазона, фильтр таблицы, loading с допуском 1 px, отсутствие переполнения при 780/390 px и мобильное меню. Визуально просмотрены Light/Dark 1440 px и Dark 390 px. Ошибок страницы не обнаружено.
- Черновик живёт только в текущей странице. Редактор токенов, сохранение черновика после reload, генерация PR, выпуск и откат ещё не реализованы.
- Первая версия опубликована на прежнем приватном адресе как версия 81 из source commit `3ba47da16e1a16b9ce72d390609fd6b793117c98`. Перед публикацией проверены хеши 535 артефактов сборки; Sites вернул `succeeded`. После выпуска access policy осталась `custom`: один разрешённый пользователь, без групп и внешних посетителей.
